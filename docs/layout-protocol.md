# 画布布局版本协议

GET `/api/journal` 在同一个只读一致性事务中返回 `structure_version`，及 entries/photos/marks 的 `layout_version`，均为十进制字符串。客户端必须保留字符串，不能转为 Number。照片版本在各记录的 photos 数组中。

PATCH `/api/journal/layout` 条件请求示例：

```json
{
  "expected_structure_version": "12",
  "items": [{ "kind": "mark", "id": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa", "x": 10, "y": 20, "rotation": 0, "expected_version": "9007199254740995" }]
}
```

全部对象按固定顺序锁定并比较后统一写入。成功返回 `{ saved, items: [{ kind, id, layout_version }] }`。结构或行冲突返回 HTTP409 `LAYOUT_CONFLICT`，不部分写入。对象缺失或非当前账号返回404；无效请求400；缺布局迁移状态503。

请求结果不明时，只能原样重试整份请求。只有所有行版本恰好为 expected+1，且坐标/旋转完全相同（照片还必须是绝对定位），才作为同值重试返回当前版本而不递增。结构已变化仍拒绝重试。禁止猜测新版本后发送不同意图。

兼容旧请求不携带任何版本，成功后也递增行版本；不能混用新旧字段或重复对象。同账号的旧页面仍可能无条件覆盖数据，升级需关闭旧页面。当前前端已接入条件布局保存：失败保留内存中的编辑，点击“重试保存”先确认原请求，再提交最新差异。页面提供撤销/重做及Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z，输入框/弹窗/示例画布不使用个人布局历史。

保存失败或有未确认请求时，刷新及增删改/导入/恢复均被屏障拒绝。409之后可确认丢弃本页布局并取得新快照；结果未知的网络失败必须先重试确认，不能假装已撤回。离开页面会触发浏览器提示，刷新不保留历史或草稿，退出及关闭页面不承诺撤销已经发出的请求。待保存差异上限500对象，超限在改变当前编辑前提示先保存，不拆分一个批量命令。

结构变化入口（创建/删除内容、组关系/折叠、手札归属、导入，以及影响相对排版的旅程创建、记录日期/旅程/照片排序变化，包括照片或记录组件中的日期/旅程变化）在事务内比较可选 `expected_structure_version` 并递增结构令牌。带位置的分组/批量照片请求在各 positions 项提供 `expected_version`；标注编辑在顶层提供两个令牌。个人 ZIP 恢复通过 multipart 字段传入结构令牌，后台worker执行同一事务检查。结构操作成功后重新读取一致性快照，不把历史游标当作数据库版本。

纯内容、手札内页排版及换页不改变画布令牌；照片/标注坐标或旋转变化检查并递增行版本。手札封面排版不在首期布局版本范围。部署前显式迁移并核验恢复点，服务启动不执行DDL。运维停写的全量恢复保留完整恢复点令牌，个人导入则生成新ID与默认版本。
