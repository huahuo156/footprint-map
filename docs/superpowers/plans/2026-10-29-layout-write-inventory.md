# M1.3 布局与结构写入口盘点

依据[已确认设计](../specs/2026-10-29-canvas-history-save-design.md)，版本协议切换必须覆盖全部相关写入口。当前运行接口仍为旧协议；`writeLayout` 是尚未接入路由的独立服务。

| 入口 | 需保护的变化 | 接入要点 |
| --- | --- | --- |
| journal PATCH /layout | 照片、记录、标注坐标和旋转 | 使用既有条件写服务；与其余入口一起切换 |
| journal POST/PATCH/DELETE /groups | 组关系、折叠状态；创建和展开时照片坐标 | 先锁账号结构行，检查结构版本；涉及坐标时按排序锁照片并比较行版本；成功结构变化递增令牌 |
| journal PATCH /photos/components | 可选照片位置以及内容 | 有位置时检查和递增行版本；纯内容更新不递增 |
| journal POST/PUT/DELETE /marks | 新增、删除标注；更新旋转 | 新增/删除递增结构版本；旋转变化检查并递增行版本 |
| journal POST/PUT /entries | 新记录、增删照片、照片移入手札 | 结构变化递增结构版本；已存在照片的纯内容更新不递增行版本 |
| journal DELETE /items、/photos、/photos/:id、/entries/:id | 删除对象及关联关系 | 事务内锁结构行并递增，失败回滚 |
| notebook 页和条目相关接口 | 对象移入手札或返回画布、级联删除 | 同一事务锁结构行；仅实际影响画布归属的变化递增 |
| backup restore worker | 导入新对象和关系 | 恢复事务先锁结构行，成功递增；归档不复用旧行版本 |
| 前端 reload 自动避让 | 初始或后续坐标修复 | 通过同一条件写入口；未确认草稿时不得覆盖 |

## 执行顺序

1. 先为共享结构锁、版本比较和溢出拒绝编写失败测试，再实现事务内辅助函数；调用者负责事务生命周期，不能在嵌套服务中提交。
2. 分批接入组、照片与标注，以及记录删除/创建、手札归属和恢复；为每类添加旧客户端递增、新客户端过期拒绝、回滚和跨账号测试。保持结构锁先于对象锁，检查现有命名锁顺序及并发死锁风险。
3. 用隔离 MySQL 验证不同连接交错：旧请求改变结构或坐标后，新页面陈旧请求返回 409 且无部分写入；失败事务不能留下令牌递增。
4. 所有入口完成并审查后，统一启用一致性 GET 和条件布局路由，再接入前端协调器及历史屏障；在这之前不对外声称冲突保护已启用。

验证须使用随机临时库，不运行于个人数据库；更新恢复和升级文档，说明升级时关闭旧页面及旧客户端仍可能无条件覆盖。
