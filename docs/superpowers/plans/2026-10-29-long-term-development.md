# 拾途长期开发计划

> 执行说明：本文件是长期路线图，不是一次性执行全部任务的指令。各里程碑开始前复查代码和需求，将当期工作拆为独立实施计划；实施时使用 `executing-plans`，只有用户选择委派方式时才使用 `subagent-driven-development`。复选框表示尚待完成的工作。

**Goal:** 将拾途发展为有鲜明旅行手帐体验、可信数据保护、可重复部署和持续维护能力的优秀 GitHub 项目。

**Architecture:** 保留 React + Express + MySQL 的现有结构，逐步明确画布交互、业务模型、持久化与资源存储的边界。先建立发布基线，再通过小步改进完善编辑体验；完整画布 SDK、离线同步和协作均经过单独验证后再决定。

**Tech Stack:** React 19、Vite、Node.js 24+、Express、MySQL 8.4、Sharp、Vitest、Playwright、Docker Compose；新增依赖需有明确收益和授权记录。

**Spec:** 依据本次项目评估与旅行应用、无限画布项目调研编写；产品原则、默认假设、阶段验收均在本文定义。远期任务在进入实施前另写设计与详细任务计划。

**日期：** 2026-10-29。**状态：** M0 本地完整检查已通过、私密报告已启用；完整验收待同提交远程 CI、素材许可及人工体验检查；见 [M0 执行记录](../../verification/2026-10-29-m0.md)。**默认对象：** 独立开发者或小团队，先提供可自托管的单实例服务；正式开放注册的公共服务需额外完成对应验收。

## 1. 产品方向与取舍

核心体验：导入旅行照片 → 关联日期与地点 → 在自由画布整理照片和文字 → 收入手札阅读与打印 → 用足迹版图回看旅行。

长期差异化集中在「自由排版的旅行回忆」：照片、文字、贴纸、分组、地图和手札之间应有连贯的内容关系。

成功的表现：第一次使用的人无需指导即可完成一篇旅行记录；编辑操作可预期、失败可见、重要修改可恢复；部署者能够独立安装、升级、备份和恢复；贡献者能够找到代码入口并运行检查。

暂缓：通用白板工具全集、社交信息流、AI 功能堆叠、实时多人编辑、微服务化、Kubernetes、完整离线双向同步。只有用户反馈或实际规模证明需要时再立项。

### 全局约束

- 保留现有 React + Express + MySQL 架构，Node.js 24+、MySQL 8.4。
- 保护已有私人数据；迁移、导入、删除和恢复需要明确失败行为及可恢复路径。
- 照片与封面继续由服务端验证登录及所有权；任何缓存、缩略图或导出改造不得绕过鉴权。
- 私人数据、凭据、备份和真实用户照片不进入 Git、测试附件或演示站。
- 延续桌面/手机、深色/浅色主题；主要编辑操作提供键盘入口，触屏不依赖 hover。
- 既有工作区存在大量未提交改动；先确认归属并整理验证，不覆盖、不自动提交全部内容。
- 本计划不授权发布到外部平台、开放注册、改变许可证或操作生产数据。

## 4. 推进节奏

以下为持续投入情况下的粗略工作量范围，不是承诺日期；每阶段结束根据真实耗时重估。前两阶段形成可试用版本，M4 完成后才评估生产发布。

| 阶段 | 大致投入 | 主要结果 | 前置条件 |
| --- | --- | --- | --- |
| M0 基线与仓库治理 | 1–2 周 | 可追溯、能复现的开发基线 | 无 |
| M1 画布基础交互 | 2–4 周 | 编辑准确、可撤销、保存可信 | M0 |
| M2 视觉与内容组织 | 2–4 周 | 统一设计和完整旅行记录流程 | M1 的数据/命令边界稳定 |
| M3 数据、性能与架构 | 2–4 周 | 大图库与异常场景可控 | M0；画布性能验收接 M1/M2 |
| M4 部署与发布闭环 | 2–3 周 | 可部署、可告警、可恢复 | M0、M3；候选版本需 M1/M2 验收 |
| M5 开源试用与打磨 | 持续 | 根据真实反馈改善稳定性 | 首个候选版本 |
| M6 可选扩展 | 按需立项 | 分享、照片库接入等 | 有需求证据且核心质量稳定 |

始终只推进一个主要产品目标和少量维护工作，避免同时改造编辑器、数据库与部署。明确的安全漏洞与数据丢失问题随时优先处理。

- [ ] 建议初始目标：500 张档位预热后平移帧耗时 p95 ≤32ms；2000 张压力档无崩溃且编辑可完成。首次可操作时间在 M0 测得基线后制定设备/网络相关预算。
- [ ] 保留现有分包门禁；新增预算需有测量方法，不能通过放宽阈值掩盖退化。

验收：性能报告可重复运行；同一条件下无明显退化；高负载照片处理、ZIP 恢复时仍可响应健康检查及普通读取。

## 9. M4：可上线与发布闭环

### M4.1 应用部署和升级

拟新增：`Dockerfile`、`.dockerignore`、`compose.production.yml`、`deploy/Caddyfile`、`docs/deployment.md`；更新 `.env.example`、`server/index.js`、发布工作流。

- [ ] 提供应用镜像和应用/数据库/HTTPS 代理部署示例，上传目录和数据库均持久化，应用以非 root 用户运行。
- [ ] 生产模板不包含可用默认密码；启动时检查必要配置并给出不泄漏凭据的错误。
- [ ] 迁移作为显式发布步骤，运行账号与迁移账号分离；支持停写维护窗口。
- [ ] 记录优雅退出、重启、健康检查和日志获取方式；图片目录不由代理公开。
- [ ] 建立带版本标签与摘要的构建产物。代码可回退不代表数据库可回退；不可逆迁移必须说明恢复备份的步骤和停机影响。

验收：在空白主机部署候选版本，完成一次旧版本升级；模拟启动失败并恢复。第三方按文档可完成这些步骤。密钥、真实数据和备份不进入镜像。

### M4.2 监控、备份与事件处理

涉及：`server/telemetry.js`、`server/operations.js`、`scripts/check-operations.js`、备份/演练脚本、`docs/monitoring.md`、`docs/recovery.md`；拟新增 `docs/incident-response.md`。

- [ ] 记录请求 ID、固定错误码与耗时，日志脱敏；接入实际告警渠道并测试到达。
- [ ] 在部署环境配置容量、服务不可用、HTTP 错误、邮件失败及备份失败告警；避免历史累计错误反复告警。
- [ ] 配置备份调度、异地加密副本、保留规则和失败通知；沿用现有停写备份条件，不将其包装成在线一致性备份。
- [ ] 以小规模服务初始目标评估 RPO ≤24 小时、RTO ≤4 小时；通过备份间隔与实际恢复演练验证，无法达到时修改方案或公开运行边界。
- [ ] 在真实部署收集 CSP 报告，解决所需资源策略后逐步强制执行。
- [ ] 用独立资料模拟数据库中断、磁盘不足、邮件失败、备份损坏和进程中断。

验收：故障能触发维护者实际收到的通知；从异地副本恢复应用并核对行数、关系与图片哈希，记录耗时和数据损失窗口。

### M4.3 对外服务与发布清单

- [ ] 自托管文档说明服务边界、容量、原图不保留及运维责任。
- [ ] 开放公共注册前完成邮件投递、滥用限制、账号注销、私人数据删除和隐私说明；确认备份中历史数据如何过期。
- [ ] 为账号删除设计重新认证、资源引用处理和删除结果；不得在没有可恢复机制时标榜可撤销。
- [ ] 形成版本号、变更记录、升级说明、已知问题和验收证据，候选版本通过后再发布。

验收：服务承诺与实际能力一致；注册开启不是默认动作；公开演示使用隔离的示例数据并控制写权限。

## 10. M5/M6：持续维护与按需扩展

每个版本保留问题清单，区分数据/安全、主要流程、体验和扩展需求。先复现问题再修复，增加针对风险的回归测试。

- [ ] 公开路线图只列承诺范围，避免把所有想法变成承诺。
- [ ] 定期检查依赖、运行文档、失效链接、CI 稳定性及恢复演练结果。
- [ ] 收集经过同意且脱敏的用户反馈，优先处理造成数据丢失、无法保存或主要流程中断的问题。
- [ ] 可选：只读分享，先定义范围、撤销、失效、位置隐私和图片鉴权。
- [ ] 可选：Immich 等照片库接入，先定义引用与复制、授权、断连和删除来源后的行为。
- [ ] 可选：地点/到访模型增强，先证明多次到访与旅行组织需求，不为模仿其他产品而迁移。
- [ ] 可选：离线编辑、多设备同步及实时协作，须先解决冲突模型、权限撤销、迁移与维护成本。

验收：每项扩展都有具体用户场景、成本分析及独立设计，不损害现有私人手帐流程。

## 11. 质量门禁与重点风险

发布候选版本必须从干净检出运行：

```powershell
npm ci
npm run lint
npm test
npm run test:security
npm run test:api
npm run check:bundle
npm audit --omit=dev
npm run test:e2e
npm run test:smoke
```

数据库与浏览器安装前提按 README/CI 执行；真实 API 与 E2E 使用随机隔离数据库。单个命令失败立即记录并处理，不因后续命令成功而忽略。依赖审计发现需评估可达性与修复方案，不盲目强制升级。

日常改动按影响范围运行检查；涉及账号、迁移、上传、恢复或发布时执行完整门禁。纯文档检查链接与内容即可，不为低风险修改机械增加测试。

### Review Focus

| 风险输入/条件 | 预期行为 | 对应验收 |
| --- | --- | --- |
| 断网、超时、乱序保存响应 | 不假报保存成功，不被旧请求覆盖 | M1.3 保存回归与 E2E |
| 缩放、触屏取消、嵌套分组 | 落点准确，无残留拖动和误选 | M1.2 输入与坐标测试 |
| 账号切换、伪造引用、缓存图片 | 不读取或修改其他账号内容 | M1.3、M3.1、安全专项 |
| 历史备份、迁移中断、失败恢复 | 明确拒绝不兼容数据或完整恢复，不部分损坏 | M3.1、M4.1/M4.2 演练 |
| 大图库、磁盘不足、处理任务堆积 | 有界资源、明确失败、基本服务可用 | M3.2 压测、M4.2 故障演练 |
