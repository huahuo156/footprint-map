## 1. 产品方向与取舍

核心体验：导入旅行照片 → 关联日期与地点 → 在自由画布整理照片和文字 → 收入手札阅读与打印 → 用足迹版图回看旅行。

长期差异化集中在「自由排版的旅行回忆」：照片、文字、贴纸、分组、地图和手札之间应有连贯的内容关系。

成功的表现：第一次使用的人无需指导即可完成一篇旅行记录；编辑操作可预期、失败可见、重要修改可恢复；部署者能够独立安装、升级、备份和恢复；贡献者能够找到代码入口并运行检查。

暂缓：通用白板工具全集、社交信息流、AI 功能堆叠、实时多人编辑、微服务化、Kubernetes、完整离线双向同步。只有用户反馈或实际规模证明需要时再立项。

### 全局约束

- 保留现有 React + Express + MySQL 架构，Node.js 24+、MySQL 8.4。
- 保护已有私人数据；迁移、导入、删除和恢复需要明确失败行为及可恢复路径。
- 照片与封面继续由服务端验证登录及所有权；任何缓存、缩略图或导出改造不得绕过鉴权。
- 私人数据、凭据、备份和真实用户照片不进入 Git、测试附件或演示站。
- 延续桌面/手机、深色/浅色主题；主要编辑操作提供键盘入口，触屏不依赖 hover。
- 既有工作区存在大量未提交改动；先确认归属并整理验证，不覆盖、不自动提交全部内容。
- 本计划不授权发布到外部平台、开放注册、改变许可证或操作生产数据。

## 4. 推进节奏

以下为持续投入情况下的粗略工作量范围，不是承诺日期；每阶段结束根据真实耗时重估。前两阶段形成可试用版本，M4 完成后才评估生产发布。

## 11. 质量门禁与重点风险

发布候选版本必须从干净检出运行：

```powershell
npm ci
npm run lint
npm test
npm run test:security
npm run test:api
npm run check:bundle
npm audit --omit=dev
npm run test:e2e
npm run test:smoke
```

数据库与浏览器安装前提按 README/CI 执行；真实 API 与 E2E 使用随机隔离数据库。单个命令失败立即记录并处理，不因后续命令成功而忽略。依赖审计发现需评估可达性与修复方案，不盲目强制升级。

日常改动按影响范围运行检查；涉及账号、迁移、上传、恢复或发布时执行完整门禁。纯文档检查链接与内容即可，不为低风险修改机械增加测试。
