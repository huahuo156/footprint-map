# 运行与迁移说明

适用于当前多账号初版。基础安装、命令和配置见 [README](../README.md)。注册默认关闭，部署和迁移由运维显式执行。

## 历史数据迁移

1. 停止 API，完整备份数据库和实际图片目录，并在副本上验证可恢复。迁移前不要开放注册。
2. `npm ci` 安装锁定依赖。保留 `.env` 并补充 `.env.example` 中的新配置。自定义 `UPLOAD_DIRECTORY` 时，运行与迁移必须指向同一目录。
3. 运维确认旧资料账号的邮箱归属，再创建账号；命令不会覆盖已有账号：

   ```powershell
   $env:INITIAL_USER_PASSWORD = Read-Host '设置旧账号密码（12–128 字符）' -MaskInput
   npm run db:create-user -- --email=you@example.com
   Remove-Item Env:INITIAL_USER_PASSWORD
   ```

4. 执行 `npm run db:migrate -- --legacy-owner=you@example.com`。若账号已经存在，可跳过建号。历史根资源和未登记的历史图片明确归给该账号，不自动赠予首个注册者。
5. 迁移发现跨所有者引用时失败，数据更新事务回滚；MySQL 已执行的 DDL 可重复运行。先修复报告的问题，再重试，不要手工写入迁移完成标记。
6. 将 API 切换到仅具 SELECT / INSERT / UPDATE / DELETE 权限的运行账号。`MIGRATION_MYSQL_USER` 和 `MIGRATION_MYSQL_PASSWORD` 仅供迁移和建号使用。
7. 启动 API，检查登录、照片读取和个人备份，再逐步恢复访问。

空数据库先执行 `npm run db:migrate`，随后创建账号。API 启动仅检查 `ownership-v1` 标记，不执行 DDL。旧 `checkins` 只在首次迁移按省份导入，原记录保留；Supabase 数据不自动导入。

## 账号与邮件

配置 `SMTP_URL`、`MAIL_FROM` 和准确的 `APP_ORIGIN`，验证邮件投递后才能设置 `AUTH_REGISTRATION_ENABLED=true`。没有邮件服务时，可用 `db:create-user` 创建已由运维确认邮箱归属的账号。

- 密码使用 Argon2id；数据库保存会话、验证与重置凭据的哈希。
- 邮箱验证链接有效 24 小时，重置链接有效 30 分钟且一次性使用，会话有效 7 天。
- 改密和重置撤销全部旧会话；未验证邮箱不能上传或还原。
- 注册已写入但投递失败时，账号保留，可登录后重发验证邮件。
- 内容、封面、私有图片和个人备份按账号隔离；写接口检查来源与 CSRF 凭据。

## 图片与备份

普通上传、封面和还原统一真实解码图片：单张最多 10MB / 40MP，旋转校正后最长边 4096px，展示文件去除元数据，不另存原图。每账号图片总量上限 512MiB；界面容量统计尚未提供。

`UPLOAD_DIRECTORY` 必须保持私有，不能由 Nginx、CDN 或静态服务器直接公开。API 鉴权读取图片并设置 `no-store`。

画布、版图、列表及手帐小图使用 `/uploads/<文件名>?thumbnail=1`，首次访问按需生成最长边 512px、质量 78 的 WebP。缩略图位于实际图片目录的 `.thumbnails/v1/` 私有缓存中，按源文件状态区分版本；每次请求仍验证登录和图片归属，并返回 `private, no-store`。固定尺寸、单个生成任务和最多 64 项等待限制控制资源占用；繁忙时已缓存的小图可直接读取，前端对失败小图最多重试两次，不自动下载大图。无需数据库迁移或重新上传旧照片。

点击照片预览或打开打印预览才加载现有 4096px 上限的大图。缩略图随原图片回收，维护任务清理孤立和过期缓存。缓存不计入账号素材额度，也不纳入个人或系统备份；恢复后会重新生成。系统备份会排除真实的 `.thumbnails` 目录，但仍拒绝符号链接及其他未知上传项。

个人 ZIP 导出、上传还原和解压总量均不超过 576MiB，清单最多 16MiB，文件总数最多 65534，不支持 ZIP64。512MiB 图片容量不变，还原会占用当前账号的剩余容量；不足时全部回滚。旧版 v1 ZIP 可直接还原。

浏览器通过 HEAD 预检后原生下载单个 ZIP；服务端逐图片产出。还原上传先落盘，只读取有界的 ZIP 索引，再逐文件异步解压、检查 CRC 与真实解码，不保留整包 Buffer。路径穿越、重复条目、重叠范围、异常压缩格式、单文件或总量超限会被拒绝。还原重新生成 ID，以当前账号为所有者；失败回滚数据并清理新文件，重复导入生成副本。

导出缺图时会提示并写入清单，缺图备份不能还原，需补回文件后重新导出。反向代理需允许至少 576MiB 文件加 multipart 开销，并设置适合大文件传输的超时；保证图片磁盘具有上传 ZIP、解码后新图片所需的临时空间。

### 图片回收

更换封面、解除手札、删除照片后检查所有照片和手札引用，只有最后一个引用消失时才回收。新关联与回收使用数据库锁协调；删除任务先提交 `staged` 标记，再删除磁盘文件及资产记录，磁盘失败时任务保留，可重试，不会把已提交的手帐修改误报为失败。

`npm run assets:gc -- --dry-run` 预览回收；确认结果后运行 `npm run assets:gc`。维护命令检查超过 24 小时的未关联上传及所有 `staged` 任务，仍有引用的图片一律保留。可由部署方安排每日运行。命令只处理登记在 assets 表中的图片，不扫描或删除未知磁盘文件。

完整部署备份必须同时包含 MySQL 与实际图片目录，包括账号和旧版数据；在停止写入或一致性快照条件下备份，并定期恢复演练。仅有个人 ZIP 无法恢复整个服务。

## 生产配置

- 全站 HTTPS，`NODE_ENV=production` 启用 Secure Cookie；`APP_ORIGIN` 精确匹配浏览器来源，无尾部斜线。
- 按实际拓扑设置 `TRUST_PROXY_HOPS`；反向代理请求大小、超时与上传和还原限制协调。
- 数据库保持内网访问；跨主机设置 `MYSQL_SSL_CA` 验证服务端证书。
- 运行账号与迁移账号分离；保护 `.env`、SMTP 凭据、地图 Key、数据库及备份。
- 检查 `GET /api/health`、邮件投递、磁盘/账号容量、错误率与数据库连接情况。
- Compose 环境变量仅在空卷初始化时生效；已有卷上修改 `.env` 密码不会自动修改数据库账号密码。

## 并发与多实例

本版本需在停服务、备份后运行 `npm run db:migrate`，新增 `rate_limits` 表。生产请求的账号/IP 限流使用 MySQL 原子计数，跨 API 实例共享，重启 API 不清零；数据库异常时拒绝受限请求。封面和色块命名锁按账号隔离。

还原的解压、图片处理和事务写入移入 `worker_threads`。API 在上传前使用 MySQL 命名锁占用每账号一个任务和全局槽位；`RESTORE_CONCURRENCY` 默认 2，允许 1–8，各实例必须一致。锁连接中断会撤销任务；工作线程最长运行 30 分钟、V8 堆上限 512MiB，原生图片内存另计。请求仍等待最终结果，不提供持久化任务队列，客户端断开后已开始的任务可能继续完成；进程中断后需检查手帐状态再重试。所有实例使用同一 MySQL 主库并共享图片目录，单个副本的本地磁盘不能用于多实例部署。

服务每小时执行一次维护，数据库锁防止多实例重复执行；也可手动 `npm run maintenance -- --dry-run` 预览后执行。运维令牌、状态接口与告警接入见 [监控与维护](monitoring.md)。完整系统恢复点创建、SHA-256 校验和隔离演练见 [恢复演练](recovery.md)。

## 已知工程边界

- 还原已有独立工作线程与共享并发门禁；尚无持久化队列、任务进度和自动重试。
- 限流与任务锁依赖单一 MySQL 主库；高可用切换及网络分区仍需部署演练。
- 已定期清理过期会话、邮件凭据、限流记录、孤立资产与已识别的崩溃临时文件；未知文件保留供运维检查。
- CSP 使用报告模式，尚未强制执行；应在真实部署中收集违规并验证后收紧。
- `test:e2e` 使用真实 API、随机独立测试库和桌面/手机浏览器，覆盖登录、上传、双账号隔离、手札、备份还原和退出。模拟界面检查单列为 `test:smoke`；旧单用户场景还需逐步迁移。
- 通用组件抽取、完整 Tabs 键盘导航及删除/解除操作的一致性仍需整理。
- 不提供分享、管理员读取私人照片或端到端加密。

验证入口与 CI 见 [README](../README.md#常用命令)。这些边界需要结合部署环境验证，仓库测试通过不等于生产部署验收完成。
