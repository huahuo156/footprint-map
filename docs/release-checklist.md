# 发布检查与证据记录

本清单用于形成候选版本的验证证据，完成本清单不自动发布、开放注册或执行生产迁移。

## 1. 确定输入

- [ ] 确认未提交改动的归属和范围，记录候选提交完整 SHA，`git status --short` 为空。
- [ ] 在新检出中验证；源码快照可用于提前排障，但不能冒充确定提交的发布验收。
- [ ] 使用 Node.js 24+、锁文件对应的 npm 依赖和专用 MySQL 8.4 测试环境。
- [ ] 浏览器测试依赖可用：Windows Edge；Linux `npx playwright install --with-deps chromium`。
- [ ] 测试机不含生产凭据；不将实际私人数据库用作测试库。

## 2. 按顺序执行

每条成功后执行下一条；保存命令、退出码和输出。PowerShell 默认不会因原生命令非零而停止，应逐条检查 `$LASTEXITCODE`。

```powershell
npm ci
npm run lint
npm test
npm run test:security
npm run test:api
npm run check:bundle
npm audit --omit=dev
npm run test:e2e
npm run test:smoke
```

`test:api` 包含隔离系统备份恢复演练；`test:e2e` 包含桌面和手机的真实 API 测试；`test:smoke` 使用模拟 API 检查深浅主题、版图和阅读焦点。`check:bundle` 内部生产构建但不落盘，浏览器检查命令会自行构建。

MySQL 必须允许隔离入口创建/删除随机测试库。详细环境变量见 [.env.example](../.env.example)，使用独立管理员凭据，不在记录中写入值。已有入口随机生成 `footprint_security_test_*` 和演练库；不得自行改为个人库。

依赖审计失败需要记录影响、修复或维护者接受风险的决定，不能直接忽略或执行破坏兼容性的强制升级。

## 3. 发布前人工检查

- [ ] 真实资料仅保留在私有存储，提交和附件无凭据/个人内容。
- [ ] 新建记录、照片导入、画布整理、地点、手札阅读、打印、备份恢复流程可用。
- [ ] 检查桌面/手机、深浅主题及主要操作的键盘焦点；截图使用示例内容。
- [ ] 迁移、配置、旧备份兼容和回退限制写入 CHANGELOG。
- [ ] LICENSE 与第三方素材分发条件明确；安全报告渠道已验证。
- [ ] 在真实部署执行健康、登录、私有图片、退出检查；生产备份/通知另按运维文档验收。
- [ ] CI 对同一提交成功；本地结果与 CI 结果分别记录，不相互代替。

## 4. 验收记录模板

复制以下内容到 `docs/verification/YYYY-MM-DD-<版本或主题>.md`，不要将未运行的项目写成通过。

```text
候选提交完整 SHA / 工作区状态：
执行日期、负责人、系统、Node/npm、MySQL、浏览器版本：
环境：干净检出 / 源码快照（写明差异和清单标识）
命令 | 退出码 | 结果摘要 | 日志/附件位置
未执行或失败的检查与原因：
数据迁移、回退和已知限制：
审计发现与处理决定：
远程 CI 地址与对应提交：
发布决定：通过 / 阻塞 / 仅开发验证
```

测试输出在 `test-results/`，默认不进入 Git；需要长期保留时使用 CI 附件或经脱敏的专用存储。基线通过必须绑定代码内容，后续改动应重新执行受影响检查。
