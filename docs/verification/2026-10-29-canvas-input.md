# M1.2 首批：拖动输入生命周期

日期：2026-10-29。基础提交 `936a9a5`，改动保留在当前工作区；这是 M1.2 的局部修复，不代表里程碑完成。

## 范围与行为

根因：`JourneyCanvas` 使用单份 drag ref，但没有记录 pointerId，第二个 pointer 可覆盖、移动或结束当前拖动；窗口失焦只重置空格键状态，没有回滚拖动；缺少丢失捕获与卸载释放路径。

现在一次手势只允许一个 pointer 拥有。其余 pointer 的 down/move/up/cancel/lostpointercapture 不影响活动拖动。拥有者取消、丢失捕获或窗口失焦时，照片、手帐、组恢复起点且不写布局；追加框选恢复原选择；普通框选沿用原有空基础选择规则。取消相机平移回到起点并记住该相机位置。组件卸载释放捕获，不提交对象位置。

正常松手仍使用原碰撞规划和保存接口；正常释放引发的 lostpointercapture 不会取消已完成手势。未引入双指缩放、依赖、数据迁移或新的碰撞规则。

## 第三批：坐标边界与滚动中的框选

抽取 `src/journal/canvas/camera.js`：统一以浏览器 client 坐标和当前 getBoundingClientRect 为输入，将视口中心、相机平移与世界缩放分开计算。模块提供 viewportPoint、screenToWorld、worldToScreen 和 zoomAt。`model.js` 保留 zoomAt 再导出，兼容既有调用；画布滚轮和框选使用新模块，照片坐标、碰撞规则及存储格式不变。

测试先确认：8%、55%、100%、240% 下的偏移视口正反框选已有实现可用；新增相机模块入口最初因模块尚未创建而无法加载，不能把它当成发现现有坐标错误的证据。独立测试使用手算坐标校验平移、倍率、滚动后的边界、投影与缩放锚点，不使用被测函数生成预期值。

进一步复现父容器在框选过程中向上滚动 100px：旧实现缓存按下时的边界，40×40 的预期选框变为 40×60，纵向起点从 330px 偏到 270px。现在每次移动读取当前视口边界，框选起点保持原世界坐标并投影回屏幕；命中范围与显示选框使用同一坐标约定。

本批新增 8 项相机测试和 6 项组件测试，含偏移视口四倍率、滚动中框选及指针锚点滚轮缩放。最终 `npm test -- --maxWorkers=1 --pool=threads`：49 文件、305 项全部通过，耗时 62.42 秒；`npm run lint`、`npm run build` 与 `git diff --check` 通过。浏览器真实滚动、CSS 外部变换及手机手势仍待验收；不宣称支持外层容器 CSS scale/rotate。

## 第四批：点击阈值与拖动中的缩放

复现：现有逻辑虽然以大于 5px 的曼哈顿距离（横纵位移绝对值之和）识别拖动，但在达到阈值前已经更新 DOM。8% 缩放时，横向 3px、纵向 2px 的手抖会把照片/手帐/组预览移动 37.5×25 世界单位；松手却按点击处理，照片和手帐未恢复该预览。相机也会把点击手抖保存为平移。

修复为未越过阈值时不更新照片、手帐、组或相机。保留已有大于 5px 的识别规则，框选不受此阈值限制。越过阈值后，返回起点附近仍属于同一拖动，按实际终点提交，不误打开对象。

另一复现：拖动或框选期间的滚轮/按钮缩放会改变当前相机倍率，使后续位移计算与手势起点不一致。当前策略是在活动 pointer 手势期间忽略缩放输入；手势结束或取消后正常缩放。不积压或延后重放滚轮输入，不引入双指缩放。

新增 10 项用例，修复前 9 项失败、1 项已有行为通过；修复后输入专项 38 项通过。覆盖照片/手帐/组阈值、相机手抖、五种活动手势中的缩放和拖动返回阈值以内。最终 `npm test -- --maxWorkers=1 --pool=threads`：49 文件、315 项全部通过，耗时 63.04 秒。lint、生产构建及 diff 检查通过。真机触屏和真实浏览器交互仍待验收，本批未操作数据库或发布。

## 第五批：退出操作结束活动手势

复现：按 Escape 或点击两处退出多选按钮时，只重置 selected/selecting，活动拖动和 pointer capture 仍然存在；后续移动和松手仍可能提交。打开手帐时也只有选择状态被清空，未回滚原有拖动。

统一 `exitSelection` 路径：先取消活动手势、恢复预览并释放捕获，再清理选框、选择和空格平移标记。Escape、退出多选按钮和结束多选按钮调用同一路径。原有输入框、输入法、其他区域及原生弹窗的键盘隔离规则保持有效。

`notebookOpen` 变为 true 时也走退出路径；手帐打开期间不再接受新的画布 pointer 拖动、缩放和画布快捷键。已提交并在等待响应的保存不属于可取消手势，本批不承诺回滚已发送的请求。

新增 11 项用例，修复前全部失败，修复后输入专项 49 项通过。覆盖照片/手帐/组/平移/框选的 Escape、两个退出入口、空格未松开时退出，以及打开手帐后的取消与输入阻断。最终 `npm test -- --maxWorkers=1 --pool=threads`：49 文件、326 项全部通过，耗时 40.81 秒。lint、生产构建与 diff 检查通过；真实浏览器与手机验收仍待完成。

## 第七批：嵌套分组的浏览器回归

在相同四种浏览器配置中加入两个成员、两层嵌套的独立夹具，并等待示例图完成解码尺寸加载。模拟布局/分组接口会更新内存夹具，保证后续 reload 与展开读取一致的测试资料。

覆盖：选择内层照片自动选中整个外层组；点击另一成员取消整组选择；拖动外层后 Escape 恢复所有成员且零写入；触屏平板的原生 touchCancel 恢复整组；完成整组拖动只发一次批量布局请求，两个成员同时平移 30×10 世界单位，横向间距保持 400；折叠外层后隐藏照片及子组，折叠封面对应的选择仍包含全部成员；重新展开保留刚才的照片坐标，且没有额外布局请求。

扩展脚本已在本机四配置通过，截图及 trace 位于 `test-results/canvas-ui/run-*/`，没有发现需要修改产品代码的新问题。该结果基于模拟 API，不代表真实数据库原子性或失败回滚通过；实体设备、真实接口失败与浏览器外部失焦继续保留验收项。

## 第八批：浏览器中的布局保存失败与重新操作

给模拟布局接口增加一次性 HTTP 503 故障，拒绝请求时不改内存中的已保存位置。单张照片与两层嵌套分组分别覆盖：错误提示可见、预览回到已保存位置、“正在保存位置”状态结束；重新拖动后成功提交。单张照片原位置为 x=30，失败后仍为 30，重拖成功为 50；整组失败后仍为 -170/230，重拖成功后为 -150/250，成员间距保持 400。

首次脚本在组场景未退出选择模式，因展开按钮替换后焦点回到 body，直接发送 Escape 被既有作用域规则忽略。已在测试操作中先聚焦画布再按 Escape，不修改产品的键盘作用域。随后四配置通过。

这是真实浏览器消费模拟 HTTP 失败的回归，未启动真实数据库；也未覆盖断网与恢复读取同时失败、乱序写响应或跨标签页冲突。当前实现采用失败回滚后重新拖动，不提供保留未保存编辑的重试入口；M1.3 的命令/历史与四态保存设计仍未实施。本轮只扩展验证脚本和记录。
