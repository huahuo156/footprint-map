# 图片画布缓存 P0：正式基线与预算

日期：2026-10-31，Asia/Shanghai。执行[缓存计划P0](../superpowers/plans/2026-10-31-canvas-image-cache.md)，当前只交付基准工具与实测报告，**尚未接入图片资源缓存或改变产品渲染逻辑**。

## 结论

500张普通平移在本机已经较流畅，但低倍概览挂载499个图片节点。2000张长会话能完成操作，却产生较高图片请求与驻留成本：10分钟191组编辑循环，媒体HTTP请求30,182次、其中28,183次为已访问URL的重复请求，完成传输约1,158MiB；浏览器进程工作集汇总结束时约1,619MiB。优化不能只看短回访命中，也不能只增加一个无限Blob Map。

下一阶段保留有界会话资源池方向，同时把视口驻留、有限解码和尺寸批量提交作为启用前提。既有服务端派生图缓存的热命中在独立函数测试中很快，本批没有支持增加Redis或更换渲染器的证据。

## 环境与方法

- Windows 10.0.19045、i9-12900H、20逻辑CPU、约15.8GiB系统内存，Node24.21.0、Edge156.0.4314.50。基线HEAD `936a9a5` 加当前codex/publication-v1未提交成果，未自动提交。
- 当前生产构建，100/500/2000张独立URL且独立像素内容的合成WebP，横/竖/方形、3个色块（含嵌套与折叠）、3张文字卡；2000个图像文件平均约40,033字节。没有使用个人照片。
- 3档 × 桌面1440×1000/触屏平板1024×844 × 深浅主题 × 每组5个独立浏览器，共60个短样本。浏览器正常缓存行为保持默认；没有禁用缓存来人为制造miss。
- 环回HTTP夹具媒体响应延迟固定20ms、未限制带宽；账号/journal/layout/group是明确模拟的接口。平板是浏览器触摸布局模拟，不能当作实体平板或实际网络的结果。
- 固定路径含平移A/B/返回、全局概览、F定位、最多500项精确微调/保存/撤销、折叠展开、真实鼠标拖动/撤销、模拟409后的确认重载。最后一例2000/tablet/dark另持续600.58秒、191组循环。
- 首次可操作由导航前安装的DOM观察器记录画布/保存就绪/工具可用时刻，独立于page.load；首图/首视口95%实际img就绪另测。rAF间隔不是GPU帧耗时，JS堆不是页面总内存，工作集汇总可能重复计入共享页。

## 十分钟压力结果

191组循环均完成，没有崩溃、断言失败或触发资源保护。完整样本共30,182次媒体HTTP请求，唯一URL1999个；其中压力段新增约28,183次请求、约1081MiB完成传输。客户端与本机HTTP夹具的请求计数一致，结束没有未完成或传输失败请求。

| 压力时间 | 工作集汇总 MiB | 私有提交汇总 MiB |
| ---: | ---: | ---: |
| 4秒 | 1202 | 1151 |
| 136秒 | 1536 | 1556 |
| 301秒 | 1525 | 1582 |
| 495秒 | 1505 | 1541 |
| 结束（600.58秒） | 1619 | 1648 |

压力段混合操作rAF p95为48.5ms，不与上表纯平移6.3ms混算。结束时JS堆约89.6MiB，而工作集汇总约1.6GiB，统计范围不同，不能把差值全部归因于图片或GPU。工作集在后半段波动，结束高于开始；单次10分钟只能说明功能连续性，不能证明没有内存泄漏或已达到低内存目标。

## P0冻结的初始预算与后续判断

下列是后续实现的验收预算，**不是新路径已经达到的结果**。绝对时间/工作集仅适用于本机浏览器与相同夹具/轨迹；其他硬件或浏览器版本先重建对照。真实页面总内存和GPU显存当前不可用，不能虚构设备绝对值。

| 指标 | 初始预算/判断 |
| --- | --- |
| 自有Blob+在途预留 | 桌面24MiB、保守档12MiB，不把在途响应排除在外 |
| 实际img/主动decode | 桌面48/2、保守档24/1；保持全量业务/选择模型 |
| Blob条目上限 | 桌面512、保守档256，仍受字节上限约束；平均40KB样本分别约19.5/9.8MiB，用足预算而非仅容纳128/64项 |
| 自有解码估算 | 桌面64MiB、保守档32MiB；不冒充浏览器/GPU真实上限 |
| 500首次工具可用/首视口就绪 | 参考机≤600ms/1500ms；另报原始样本，不改成等待所有图片 |
| 500预热平移 | rAF p95≤32ms，且同环境A/B不明显退化（容忍界为max(旧路径20%,2ms)） |
| 500浏览器工作集代理 | 新路径同口径峰值目标：桌面≤650MiB、保守档≤640MiB；与旧路径逐项A/B验证 |
| 2000压力 | 10分钟功能连续；同口径工作集目标≤1100MiB，混合操作rAF和请求/字节单独报告；原3GiB/1GiB可用内存保护仍保留 |
| 网络复用 | 对有重复请求的同驻留策略、同预算/TTL可复用场景，目标减少80%；分母为0的短回访标N/A，不能制造miss或宣称减少100% |

P1仍实现有界会话资源池，但P3驻留控制是新路径启用前提。三组A/B（旧路径、仅驻留、驻留+缓存）分别归因，避免把少挂载图片的收益全部计成缓存命中。长会话重复流量必须纳入验证，不能只用一次很短的返回路径作缓存结论。
