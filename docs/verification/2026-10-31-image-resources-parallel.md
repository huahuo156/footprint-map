# 图片资源 P1/P2 并行开发验收

日期：2026-10-31。用户明确要求全力推进并使用子代理，主线程与三个子代理分文件并行开发，完成后统一审查和回归。

## 本轮交付

- P1 有界队列与优先级：唯一排队资源最多桌面 64 / 平板 32；超额需求为 deferred，前台显示需求优先，释放后自动补位。
- 显示租约最多 48 / 24；共享 URL 的不同实际消费者分别计费。解码工作集估算预算 64 / 32MiB，每个显示名额和正在执行的探测器各按 1MiB 计费。申请显示名额时保守预留全部 decode 探测槽，避免预算死锁。
- 单 key 共享 503/网络失败的 800/1600ms 退避；取消、401/400/404、格式/大小校验失败不重试，不回退原图。重试包装仅在核心一层，避免叠加成九次请求。
- 可取消原生 Image.decode 探测器；单图尺寸不超过固定 512px，成功、失败和取消均清理探测器 src、临时 URL 和监听器。探测器与显示 URL 分别拥有、分别释放。
- 固定桌面/平板 profiles 和默认私有传输/解码工厂。初始按粗指针或宽度 <=1024 选择保守档；本轮不实现活动窗口实时切档。
- P2 会话控制器：API epoch 重置同步关闭缓存，重新只读验证归属后才恢复；同一验证请求合并，旧成功/失败均不能污染新会话；离线到期关闭资源，显式前台重试恢复。
- 会话缓存创建后最多 60 秒整体轮换，命中和前台校验均不延长旧缓存寿命。这比每个资源按网络完成单独计时更保守；用一个计时器处理最早会话/缓存期限，可能更早回收刚加载的资源，后续 A/B 需如实反映请求代价。
- React Provider/useImageResource：StrictMode 生命周期、同源多租约、scope 切换、前台检查、已删除私有成员 diff、公共/本地预览与大图绕过。成员只按规范化私有源比较，文字和布局修改不触发像素失效。
- JournalImage 新增可选 resourcePolicy="canvas"，仅在显式策略和 Provider 内使用资源；没有可用缓存时显示占位，不偷偷直接请求私有原图。既有默认路径保持兼容。
