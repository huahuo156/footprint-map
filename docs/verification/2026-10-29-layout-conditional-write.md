# M1.3 第三批：条件布局事务服务

新增 `server/layout-versions.js` 的 `writeLayout(connection, authenticatedOwnerId, payload)`。拥有 begin/commit/rollback，不建立或释放连接；ownerId来自调用者认证上下文，不读取请求body中的账号。**尚未接入运行路由、GET快照或其他写入口，不宣称产品已经具备并发版本保护。**

先复制并验证输入，按账号结构行→kind+id对象行的确定顺序加锁；全部检查完毕才更新。支持photo/entry/mark、1–500项；新版本协议拒绝结构令牌/对象版本混用和重复对象，UUID大小写归一。版本以十进制字符串读取、BigInt计算和字符串返回；达到无符号64位上限拒绝继续递增。

所有对象版本匹配才整批写入并+1；同值重试必须全批均为expected+1且坐标/旋转相同，照片已固定为绝对位置，此时只确认、不增加版本。新写/重试混合、不同值旧请求及结构冲突返回409 LAYOUT_CONFLICT；无所有权/缺失对象404且不泄露他人信息；缺账号结构行503。无版本legacy调用仍可写入并增版本。

## 验证

先写测试观察缺模块失败，随后实现。定向单元覆盖正常写、严格重试、晚成员冲突不更新前成员、缺失所有权、坏版本/坐标/重复ID与等待事务期间的输入快照。额外复现数组kind被隐式转字符串的问题，新增失败用例后加入严格string校验。

真实数据库用例加入现有 `test:layout-migration` 入口；脚本仍不读.env，使用随机临时库与原schema。首次标注夹具缺captured_on导致失败，补齐真实表的必填字段后通过，没有修改产品schema去适应测试。

隔离 MySQL 8.4：专用容器 `footprint-layout-protocol-6747da52`，环回33317、512MiB/1CPU/tmpfs；覆盖：

- 正常写入、同值重试不增版本、混合新写/重试拒绝、照片非绝对状态不能假装已重放。
- 批量冲突与跨账号对象拒绝，前面的有效成员没有部分更新。
- 结构令牌变化拒绝旧请求，大于2^53版本保持精确，legacy写也递增。
